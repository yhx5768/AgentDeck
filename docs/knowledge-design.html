AgentDeck · Design Preview · 2026-11-09

资料空间

把任务产物沉淀成可检索、可追溯、可审批的知识。 每条知识都能回答：从哪来、谁确认、现在还算不算数。

KnowledgeEntry + FTS5 独立 data/knowledge.db 自动只出 draft 人工/主 Agent 审批 不扫描工作区
01

四个概念，别混

知识不是台账，不是 memory，也不是原始文件。

Knowledge

知识条目

一条结论、方法、决策或资料 pointer；带来源、审批、过期状态。

回答「以后还能用吗」
Ledger

工作台账

项目/事项的当前状态与时间线，持续更新，不作为可复用结论。

回答「现在做到哪了」
Memory

Agent 记忆

用户偏好、长期事实、工作方法；启动即进上下文，小而精。

回答「以后该怎么做」
Artifact

原始产物

HTML / Markdown / 文件 / 外链本体；append-only，是证据不是结论。

回答「交付文件在哪」
判据：现在做到哪 → 台账；以后遇到同类问题怎么做 → 知识；你以后都要这样 → memory；这次交付的文件本体 → artifact（知识只引用它）。

03

自动采集：从任务完成到搜索命中

自动只写 draft；用户原话决策是唯一可自动 approved 的窄类。

1

任务完成

状态 → 待验收 / 已完成；采集器读取任务、timeline、artifact。

2

抽取 + 脱敏

Markdown/HTML/CSV/JSON 文本化；敏感串脱敏或隔离。

3

去重 + 证据

dedupe_key 命中就合并证据；否则新建 draft，写 evidence。

4

审核

主 Agent / 用户通过后变 approved；AI 摘要不能自动通过。

5

检索复用

worker 搜索到 approved 条目，带证据和 artifact 链接。

例子：任务「梳理 SSE 回放与 rewind 的 seq 语义」完成 → 采集到结论「sendSeq 与存储 seq 无关，rewind 用 checkpoint uuid」→ 生成 draft K-20261109-183012-a1b2 → 主 Agent 搜索「SSE 重编号」命中 → 审核通过 → 第二天 worker 搜「重编号」直接复用。
04

数据模型与状态机

条目、证据、关系、版本、审计分开存；FTS 是派生索引。

KnowledgeEntry 关键字段
id, title, summary, body
project, tags[], owner, created_by
status, confidence, sensitivity
source_kind, source_task_id
source_session_id, source_artifact_ids[]
source_paths[]          # 只标注，不读文件
dedupe_key, content_hash
generated_by, ai_fields[]
version, supersedes_id
last_verified_at, valid_until
reviewer, reviewed_at, review_reason
created_at, updated_at, deleted_at
状态机
draft → approved → stale → superseded
rejected · quarantined 敏感命中 → 隔离，不进 FTS，TTL 7 天

默认搜索只返回 approved；draft 只有主 Agent / 创建者可见；stale 默认不返回，需显式 include_stale。 过期条件：last_verified_at 超期、valid_until 到期、来源任务/产物缺失。

对象作用权威性
knowledge_entries知识卡当前版本与状态当前投影
knowledge_evidence任务 / 产物 / 会话 / 路径来源与引用来源权威
knowledge_relationsrelated / supersedes / conflicts_with关系权威
knowledge_revisions每次编辑的旧版本历史
knowledge_events创建/审批/驳回/隔离等审计不可变审计
knowledge_fts标题/摘要/正文/标签的 CJK 分词索引派生，可重建

06

MCP 工具与权限

Agent 优先；worker 可搜索、可写 draft，不可审批。

工具 / 操作worker主 Agent说明
knowledge_search✓✓worker 只看 approved，排除 sensitive/secret
knowledge_get✓✓自己创建的 draft 可按 id 读
knowledge_add✓✓默认 draft；必须带 source_task_id 或明确 manual
knowledge_link（related）✓✓只加弱关联
knowledge_review✗✓两层闸门：工具表不暴露 + 服务端 requireMainAgent
knowledge_link（supersedes）✗✓替代旧结论要主 Agent
knowledge_delete / collect / backup✗✓删除、采集、备份是管理操作
用法：主 Agent 派工前 knowledge_search，收尾时 knowledge_add（带 task_id 和 artifact id）；worker 开始前搜索、结束后写 draft。 审批永远由主 Agent 或用户在 UI 完成。
07

治理与安全

宁少一条知识，不漏一个凭据。

敏感扫描token / cookie / password / 私钥 / 高熵串；命中即脱敏隔离，不进 FTS。
采集边界不扫工作区、不读原始 transcript、不读 legacy report_file 路径、不抓外链。
访问控制所有 API 走 gateway token；审批走主 Agent 两层闸门；当前是单用户控制台。
审计创建/编辑/审批/驳回/隔离/删除全记录；不把敏感原文写进审计。
保留期draft 30 天、stale 180 天、隔离 7 天、软删 30 天；审计 1 年。
可撤回驳回立即下架；purge 删正文/索引，保留审计元数据；误收凭据提示轮换。
08

分阶段计划

先把「draft → 审核 → approved → FTS 搜到」闭环做通。

P0

最小可用

  • 独立 knowledge.db + FTS5 + CJK 分词
  • 手动 / 任务完成生成 draft
  • MCP search/get/add/link/review
  • 资料空间页 + 任务抽屉「相关知识」
  • 基础敏感扫描 + 隔离
≈ 8–12 人日
P1

自动抽取 + 审批

  • Markdown/HTML/CSV/JSON 抽取
  • job 队列、重试、启动恢复
  • 审批队列、stale 复核、审计 UI
  • 相关条目建议、curator 摘要
  • 可选的用户文件上传
≈ 12–18 人日
P2

语义与分享

  • 语义检索（先评测再决定）
  • 周报/日报知识摘要
  • 只读分享链接 / 深链完善
  • 从 memory / work-tracking 手动导入
  • 多用户 ACL（如产品化）
≈ 15–25 人日
为什么不先做向量库：当前知识量级千条以内，FTS + 项目/标签/来源过滤够用；没有真实查询日志前，无法证明语义检索的收益。 触发重新评估：approved > 5,000，或真实查询集 FTS 召回 < 80%。
09

验收口径

可检查、可回归，不靠感觉。

P0 必须全过

  • 中文 2 字、3 字查询都能命中
  • 任务完成只生成 1 条 draft，重复触发不新增
  • worker 不能审批；主 Agent 可以
  • 敏感串隔离且不出现在 FTS/worker 搜索
  • 任务抽屉显示相关知识，点击可打开详情
  • canary 文件证明没有扫描工作区
  • go test ./... 与前端测试全绿

P1 追加

  • artifact 发布 → 1 条 draft；HTML 脚本不入正文
  • 重复 artifact 不新建，证据合并
  • 审批队列批量操作；stale 到期/复核
  • curator 超时不影响确定性 draft
  • 备份 → 恢复 → 重建 FTS 后搜索一致
  • 1 万条 entries 查询 P95 < 100ms
